# RAPID

Software component of a capstone design project.  
Streams GDS2 lithography patterns to an FPGA over UART for motor-driven stage control.

**Team:** Jack Parrack, Laurel Leuwerke, Matt Bracker, Chance Besancenez

---

## Overview

RAPID reads a GDS2 input file, converts the XY coordinates to polar form, and transmits each point as a framed binary packet over a serial COM port to a Zynq FPGA.  The FPGA acknowledges every received point; the PC waits for each ACK before sending the next (stop-and-wait flow control).  A Python dashboard provides real-time visualisation of the acknowledged points.

```
input.gds  ──►  inputParser  ──►  pcCommunication  ──►  UART  ──►  fpgaCommunication
                (XY → polar)       (frame + send)                    (receive + ACK)
                                         ▲                                  │
                                    dashboard.py  ◄────── ACK log ──────────┘
                                  (live XY scatter)
```

## Dependencies

### PC (Windows)
| Tool | Purpose |
|------|---------|
| MinGW-w64 / MSYS2 UCRT64 | C compiler (`gcc`) and `make` |
| Python 3.11+ | Dashboard |
| PySide6 | Qt GUI framework |
| pyqtgraph | Real-time plotting |

Install Python dependencies:
```
pip install -r requirements.txt
```

`gcc` and `make` are provided by MSYS2. If `make` is not on your PATH, add `C:\msys64\usr\bin` to your user environment variables.

### FPGA
- Xilinx Vivado + Vitis (tested on the Zynq-7000 series)
- `src/fpgaCommunication.c` and `src/fgpaConfiguration.c` must be built inside a Vitis bare-metal project — they are **not** part of the PC Makefile.

## Building & running

### 1 — Build `transmission.exe`
```
make
```
Output: `build/transmission.exe`

### 2 — Launch the dashboard
```
make dashboard
```
or directly:
```
python src/dashboard.py
```
The dashboard will:
- Let you select the COM port and GDS file
- Launch `transmission.exe` as a subprocess
- Plot each acknowledged polar point on a live XY scatter chart
- Display ACK / CRC error counters and a scrolling log

### 3 — Run without the dashboard
```
make run PORT=COM25 FILE=input.gds
```

### 4 — Clean build artefacts
```
make clean
```

## Packet wire format

Both `pcCommunication.c` and `fpgaCommunication.c` use the same framing:

```
[ 0xAA | 0x55 | TYPE | LEN | PAYLOAD (LEN bytes) | CRC8 ]
```

| Direction | TYPE | LEN | Payload |
|-----------|------|-----|---------|
| PC → FPGA | 0x01 | 8 | `r_nm` (int32 LE) + `theta_udeg` (int32 LE) |
| FPGA → PC | 0x81 | 8 | Echo of received payload (ACK) |
| FPGA → PC | 0xF0 | N | Debug / status string |

CRC is XOR over `[TYPE, LEN, PAYLOAD...]`.

## FPGA GPIO config-word (fgpaConfiguration)

Controls the motor driver over AXI GPIO (Channel 1, lower 7 bits):

| Bits | Function |
|------|----------|
| [1:0] | Spindle speed (0–3 → 25/50/75/100 % duty cycle) |
| [2] | Spindle direction (0 = reverse, 1 = forward) |
| [3] | Spindle enable |
| [4] | Stepper direction (0 = reverse, 1 = forward) |
| [5] | Stepper enable |
| [6] | Stepper reset (active-high pulse) |
